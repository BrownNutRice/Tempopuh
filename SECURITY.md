# Security reporting

## Scope

Reports for this repository should identify the affected fork version/commit and component. Historical previews are retained for reference; no long-term support window is promised.

## Report responsibly

If GitHub's private vulnerability-reporting option is available on this repository, use it for sensitive details. If it is unavailable, open a minimal public issue requesting a private reporting channel without disclosing the vulnerability, exploit, private records or credentials. Do not send fork-specific sensitive information to an upstream address unless its owner has agreed to receive it.

Include impact, prerequisites, affected versions and a safe reproduction using synthetic data through the agreed channel. Do not test against other people's devices/accounts or publish live pairing/OAuth credentials.

## Handling

Maintainers can acknowledge, investigate and coordinate fixes through available channels; no response-time or security-certification guarantee is made. Released artifacts should be tied to source commits and checksums. Signing-certificate continuity is a separate requirement from checksum verification.

For normal troubleshooting use [SUPPORT.md](SUPPORT.md). Privacy behavior is documented in [PRIVACY.md](PRIVACY.md).
