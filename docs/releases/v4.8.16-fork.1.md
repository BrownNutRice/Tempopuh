# Tempo 4.8.16-fork.1 — First Fork Preview

> Historical release retained under its original tag. New releases use the SemVer format documented in [RELEASING.md](../RELEASING.md); the existing tag and APK are not rewritten.

**16 November 2026 · Android 8.0+ · APK distribution via GitHub Releases**

This is the first publicly downloadable preview of the
[Tempo fork](https://github.com/matchalattewithbanana/Tempo), built on
[avinaxhroy/Tempo](https://github.com/avinaxhroy/Tempo). It brings together
local-first playback tracking improvements, consistency fixes and a major
repository maintenance pass. This fork is **not** the upstream Google Play
release.

## Highlights

### Listening tracking and live feedback
- Reduced the completed-play persistence batch delay from up to 30 seconds to
  approximately 750 milliseconds, with Home/History/Stats refreshes following
  successful database writes rather than racing ahead of them.
- Improved elapsed-time accounting using Android's monotonic
  `elapsedRealtime`, excluding reported pauses and accommodating playback
  while the CPU is suspended.
- Separated **actual listening seconds** from media position/track-completion
  coverage, helping avoid inflated time from seeks or different playback
  speeds. Added MediaSession position interpolation when Android provides
  playback anchors and improved notification-only fallback.
- Added a provisional, ticking **Listening this session** timer on Now Playing,
  without counting unfinished sessions in final statistics.
- Added anonymized session timing diagnostics to help investigate the
  previously reported one-minute-per-track symptom.

### Trustworthy histories and statistics
- Consolidated authority-ranked local and Spotify API insertion paths to
  reduce duplicate plays regardless of which source arrives first.
- Preserved distinct repeated listening sessions and legitimate simultaneous
  browser/desktop and Android playback.
- Fixed unknown imported completion being mistaken for an actual skip and
  excluded missing completion evidence from relevant averages.
- Corrected average/longest listening-session calculations: sessions are
  grouped from playback events and actual listened milliseconds, rather
  than dividing totals by active days or counting idle time.
- Added **Settings → Your Data → Check listening-history accuracy**. This
  optional scanner can identify old Spotify recently-played records whose
  listening duration or completion was previously guessed. Its correction
  requires explicit backup confirmation, never deletes play records, and
  leaves other reconstructed history unchanged.

### Spotify sync and background behavior
- Spotify Device Broadcast Status and Android MediaSession/notifications
  remain primary for local, timely updates.
- Spotify API history reconciliation is scheduled for approximately every
  **20 minutes** through WorkManager, instead of continuously polling
  playback state every 45 seconds in the foreground.
- Added bounded backwards pagination and cursor safety checks when
  Spotify exposes multiple pages of recent listening history. Empty,
  overlapping or incomplete pages cannot silently skip forward.
- Improved import concurrency, cancellation behavior, source identity
  checks and protection against stale/forged broadcasts.

### Stability, privacy and project quality
- Hardened local browser-companion request signing against replay by
  requiring timestamps and nonces.
- Corrected HTTP retry behavior for retryable responses and server rate limits.
- Fixed several refresh/cache synchronization paths and added unit and
  Android database regression tests.
- Reorganized the README into a concise project overview with links to
  focused setup and architecture documentation.
- Removed generated `node_modules` dependencies from Git history's active tree
  while retaining lockfile-based reproducibility.

## Installation / upgrading

1. Download the attached `Tempo-4.8.16-fork.1-preview.apk`.
2. **Back up Tempo data before installing**. This is a **debug-signed preview
   APK**. If its certificate differs from your installed version, Android
   will reject an in-place update; you may need to uninstall the old app
   after safely exporting data.
3. Grant Notification Access and any permissions required by your player.
   For Spotify Device Broadcast Status, enable the feature in both Spotify
   and Tempo if your Spotify app supports it.

## Important limitations

- **Playback accuracy on real devices is not yet certified.** Build and
  unit-test success do not demonstrate that all Spotify versions, media
  players, screen-off playback, or the earlier one-minute-duration problem
  behave correctly. Reports with elapsed listening time and raw event
  duration are especially helpful.
- **Debug signing:** this APK is a preview, not a production-signed release.
  If no persistent debug signing key is configured in the build repository,
  future runner-generated debug signatures may differ, preventing in-place
  upgrades. Do not use this APK as the sole backup of listening history.
- **Google Drive sign-in requires your own OAuth setup**, including a Web
  client ID and an Android OAuth client registered to the APK's actual
  signing SHA-1. See [Google Drive setup](../GOOGLE_DRIVE_SETUP.md). It
  cannot be assumed functional in an unconfigured fork build.
- The Spotify recently-played API has a **50-item page size and a
  server-controlled history window**; pagination cannot recover unavailable
  older history. Use Spotify extended-history export for comprehensive
  older data. Spotify API records do not contain exact listened duration.
- Background jobs run when Android permits. A 20-minute WorkManager
  interval is a **request**, not a guaranteed execution time.
- The browser companion may require updating to the current extension,
  because replayable body-only request signatures are no longer accepted.
