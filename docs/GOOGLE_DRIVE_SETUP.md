# Google Drive backup — fork setup

The fork preserves the **original Tempo** Google Sign-In, Drive authorization,
backup/restore UI, encrypted token storage and scheduled backup code. Those
sources are identical to `avinaxhroy/Tempo`. The difference is how this fork's
GitHub-built APK receives the OAuth configuration.

## Why the GitHub APK says "Google Sign-In not configured"

GoogleAuthManager reads `BuildConfig.GOOGLE_WEB_CLIENT_ID`. The original
`app/build.gradle.kts` populates it from `local.properties`, which is ignored
by Git. A GitHub Actions build therefore has an empty value by default.

This fork accepts the same `GOOGLE_WEB_CLIENT_ID` via the GitHub Actions
**repository variable** as well; there is **no Google client secret** in the APK.

### Set up a Google Cloud project

1. Create/select a Google Cloud project and enable the Google Drive API.
2. Configure the Google OAuth consent screen and add your Google account to
   its test-users list if the consent screen is in Testing.
3. Create a **Web application OAuth client**. Copy its Client ID
   (normally ending in `.apps.googleusercontent.com`).
4. Create an **Android OAuth client** for application ID `me.avinas.tempo`.
   Register the SHA-1 fingerprint of the certificate that signs the APK
   you actually install. GitHub's default autogenerated debug signing keys are
   not a reliable shared fingerprint across runners.
5. In the fork, open **Settings → Secrets and variables → Actions → Variables**,
   and add `GOOGLE_WEB_CLIENT_ID` with the Web application client ID.
6. If building locally, keep the original `local.properties` setting:
   `GOOGLE_WEB_CLIENT_ID=YOUR_WEB_OAUTH_CLIENT_ID`.

### Optional: stable signing of GitHub APK artifacts

To make the SHA-1 you registered in Google Cloud reproducible, create your
own private debug keystore and set these GitHub Actions **repository secrets**:

- `TEMPO_DEBUG_KEYSTORE_BASE64`: base64 encoding of your own JKS/keystore bytes
- `TEMPO_DEBUG_STORE_PASSWORD`
- `TEMPO_DEBUG_KEY_ALIAS`
- `TEMPO_DEBUG_KEY_PASSWORD`

Generate a keystore locally, for example:

```sh
keytool -genkeypair -v -keystore tempo-debug.jks -storetype JKS \
  -alias tempo-debug -keyalg RSA -keysize 2048 -validity 10000

keytool -list -v -keystore tempo-debug.jks -alias tempo-debug
# Read the SHA1 fingerprint to register for the Android OAuth client.
base64 -w 0 tempo-debug.jks
```

Never commit the keystore, private key or passwords to Git. The APK build
workflow only restores the keystore when the secret exists; otherwise it
continues building a standard debug APK. Avoid sharing the base64 value, which
contains the private key.

**Important:** Android does not permit installation over an existing app
signed with a different certificate. Make a local backup before uninstalling
the old app if its signing certificate differs.

## Within Tempo

1. Open **Settings → Backup & Restore → Google Drive**.
2. Tap Google Sign-In and complete account selection.
3. Complete the `drive.file` authorization prompt.
4. Enable Google Drive backup and run a manual backup first.
5. Confirm that the backup appears in the Google Drive backup list before
   relying on an automatic schedule.

The app only accesses Drive files created through the `drive.file` scope.
A configured Web client ID **alone** does not prove that Android OAuth
signing, consent-screen authorization, account permissions and Google Drive
access work. Test with an APK built using your own OAuth credentials.

## Limitations

Repository GitHub connectors cannot provision your Google Cloud OAuth
clients, consent-screen test users, or private signing key. Those must be
provided by the app owner; the source cannot safely assume another
developer's OAuth credentials or signing certificate.
